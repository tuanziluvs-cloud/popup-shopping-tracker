# 快闪代购采购单

现有 GitHub Pages 单页应用：<https://tuanziluvs-cloud.github.io/popup-shopping-tracker/>

保留圆角卡片、活动管理、商品目录、多商品订单、队列及采购单。

## 使用

1. 点击右上角「登录云同步」，注册邮箱和密码，打开确认邮件，再返回登录。若确认邮件跳转至 localhost，邮箱通常已经确认，返回网页登录即可；也可粘贴邮件确认链接完成验证。
2. 电脑和手机使用同一个邮箱账户。仅在成功读取/写入数据库后显示「云端已同步」。页面显示「本机保存」「待同步」或「同步失败」时，数据尚未确认上传。
3. 录入旧订单的原浏览器登录后，先下载本机备份，再点击「合并本机数据到云端」。旧键 `popup-proxy-v1` 始终保留。按订单不可变 ID 去重，保留原编号、原创建时间（若有）及队列；旧版从未存储的时间不伪造。
4. 离线修改使用按账户隔离的持久待上传缓存，恢复网络后自动重试；页面打开时每 5 秒检查更新。退出前要求完成同步。同一浏览器同时打开多个标签页时，一个标签页可编辑，其余只读。
5. 修改同一订单的相同字段时若出现冲突，请选择冲突字段采用哪个版本。其他设备新增的订单仍保留。采购 +/- 按差量合并；每次请求有唯一写入 ID，防止丢失响应后的重复计数。

## 云端及权限

`cloud.js` 只含允许公开的项目 URL 和 publishable key，不含 secret/service_role key。Supabase Auth 使用邮箱密码，RLS 将 `shopping_state`、`shopping_writes` 限制为 `auth.uid() = user_id`。未登录角色没有表访问权限。真实顾客数据不能提交到仓库。

`shopping_state` 按账户保存 JSON；乐观版本检查及字段合并防止旧快照覆盖新订单。事务 RPC `apply_shopping_write` 将写入和请求收据原子提交。数据库触发器验证结构、采购数量、订单引用，禁止删除已有订单/活动或修改订单编号及创建时间。活动仍可归档。SQL 记录在 `database/`，已经应用到现有项目；不要重复执行创建语句。

## 验证

```sh
node --test tests/sync-core.test.cjs
node tests/app-simulation.cjs
```

第一组覆盖合并规则；第二组运行实际页面脚本，以两个隔离的存储/应用上下文及模拟网络覆盖新增、修改、队列、分配、并发采购、掉线重载、丢响应重试、迁移去重、冲突处理和图片路径。模拟网络通过不代表已完成真实账户的双设备验收。

`tests/database-rollback.sql` 已在实际 Supabase 执行通过，验证真实 RPC、RLS、版本冲突、幂等、订单身份保护和非法数量。测试使用事务内无密码临时身份，最后回滚，没有创建持久可登录测试账户。

可选 `tests/browser.cjs` 供具有 Playwright 和 Chromium 的环境运行（`CHROMIUM_PATH` 可设置路径）；当前执行环境禁止启动 Chromium 所需的本地 socket，因此此脚本未在本环境完成，不能视为已通过。

仍需由账户所有人在网页完成邮箱注册/确认及首次本机迁移，再以手机和电脑的真实登录状态核验。现有浏览器的私有数据无法由 GitHub 插件读取。

线上人工浏览器检查已通过：32 张官图加载，340 CSS px 窄屏目录和订单录入无横向溢出，购物篮加减正常，按钮尺寸至少 44px。完整自动化浏览器脚本仍受上述运行环境限制。
